# 可复用的原厂限充研究流程

本教程复用研究过程，不复用其他机器的地址。先将Windows调用桥和EC内部策略分别定位，再在明确授权下组合验证。案例平台是NLYA/TP181；[协议](PROTOCOL.md)只属于此已确认组合。

## 1. 固定身份、来源和原始字节

记录整机、主板、BIOS、原厂软件版本和已有设备入口。只读采集所需元数据，避免导出不必要的序列号。已有ROM先SHA256复核，不重复导出；离线下载包记录URL、版本、哈希和解包方法，不执行OEM更新器。

区分BIOS导出、完整SPI备份、EC候选和当前运行EC：导出成功不等于完整SPI，ROM中含候选不等于当前运行EC全部内容。将来源与镜像哈希独立保存，见本例 [SOURCES.json](SOURCES.json)。

## 2. 识别架构和代码银行

从镜像结构、签名、复位向量、代码密度和厂商材料识别候选。先建立文件偏移、代码银行和逻辑PC映射，再反汇编；把银行切换误当线性代码会产生错误调用链。

搜索电量百分比、维护变量和主循环消费者，但字符串、菜单名或变量名只是候选。沿消费者追比较、充电器状态、参数生效条件和默认恢复分支。

## 3. 接出宿主可达接口

```text
宿主命令分发 → 参数验证 → RAM状态
                              ↓
主循环读状态 → SOC比较 → 充电 / 保持 / Learn
                              ↓
查询回读 + 取消恢复 + 存储范围审计
```

每个候选用同一张表记录：本机版本、入口、参数、字段、实际消费者、读回、恢复、非易失存储风险和睡眠未知项。只找到字符串或其他型号代码不能进入硬件控制。

NLYA已确认73设置、92固定查询、74取消；设置/取消handler的有界审计没有发现Flash/UEFI写入器。不能把这个结论扩大为全固件无存储写入。也不要写ROM或修改NVRAM来“开启隐藏接口”。

## 4. 分层解决Windows桥

Intel固定元数据请求错误1/C0000002，说明该请求未被当前路径支持，不证明EC没有策略。原厂CCDRV1打不开需要查设备入口、服务加载及签名；本机原厂桥遇到577拒绝，随后使用已授权的签名临时桥完成固定PMC2读回。

不要扫描未知IOCTL/SMI来碰运气，不改安全策略，也不要自动重试未完成的多字节事务。桥能开不代表命令兼容；必须核对芯片、修订、构建标识、白名单、状态和恢复路径。

## 5. 交叉比较同平台材料

同模具的神舟、七彩虹、雷神包可比较DLL、命令编码、设备名和消费者。蓝天/同方/广达线索用于缩小平台范围，同GUID或同DLL不构成完整充电兼容证据。

星耀14借鉴的是软件到EC的定位、回读和验证方法，其F1/F2/F3与两阈值语义不能直接移植成本机的73/74/92。不同品牌的重复DLL本身可能是协议族证据，应记录来源而非按哈希盲目删除。

## 6. 先模拟，再授权实机

模拟目标边界、拔插、坏遥测、超时、读回矛盾、日志失败、进程退出和恢复失败。当前发布测试只调用FakeApi/Ec，不操作硬件。实机前保存基线，确认可取消且有可靠读回，再做单次有界实验。

原例短时实验约11秒时因PowerOnline变化提前退出，取消及独立恢复通过；不能因为外层probe成功而说整轮20秒成功。高SOC主动放电和Windows供电位变化随后分别分析，没有仅靠一个位断言拔插。

## 7. 交付面板与证据

UI只提供确认过的固定操作。身份不匹配拒绝，未知状态锁住控制，日志先写意图再I/O，控制不盲目重试。成功开启后关闭是否保持必须是明确产品决策，本例选择保持；不要把旧软件轮询策略混入原厂运行期行为。

文字、图形和布局一起按DPI缩放，绘制子进程在创建窗口前初始化。模拟截图标注模拟，命令回读、短时保持和完整充电分开记录。原例一分钟80%保持仍需低电量充到目标、30分钟和两次过程补齐。

## 8. 制作可公开仓库

单独列白名单复制源码与说明，不复制整项目。排除固件、OEM包、用户目录、会话、序列号、Git历史和私人恢复材料；保留来源URL、版本及哈希摘要。第三方驱动分发必须有原许可并保持签名。路径脱敏后仍保留明确部署检查，不能为了便携去掉保护。

按文件生成清单，扫描秘密和路径，核对所有相对链接，实际解压逐文件比较，再从解压副本执行模拟测试及预览。公开包完整性不等于硬件兼容。维护时保留原资料和删除恢复包，但不把私人恢复包上传。
